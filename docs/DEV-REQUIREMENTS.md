# DEV-REQUIREMENTS · gca-workbench 开发需求与纪律

版本 v0.1 · 2026-11-14 · 自动签认状态：夜班无人值守草案，晨审未追认。默认值见本文 §五与 DEV-PLAN §五。

## 一、四条总原则

1. 原型是唯一视觉与交互基准，开发版逐项对齐（ui-parity 逐字符）。
2. 事实与演示数据各有唯一来源（demo 合成档案为演示唯一源，全部标注「合成示例」）。
3. 没有实测不写通过（闸口逐项实测；SKIP 不计覆盖）。
4. 每项约定写清适用语境、反例与可执行验收。

## 二、患者视角红线

- 功能按患者关心的信息维度组织（化验/发作/视力/用药/影像）；医生任务冒充患者需求属独立评审一票否决。
- 每条功能线挂证据层级；0 患者访谈如实声明，改写句不冒充引语。
- 0 临床审核必须标注；阈值一律【待核】。

## 三、非肿瘤语义红线

- 全站禁词：分期 / 线序 / 疗效 / 预后 / 生存期 / 病期 / D+N / day_index。
- 发作—缓解区间带替代症状色块；「较上次」替代下降级箭头。
- GCA 无肿瘤监测条目（与肝胆类慢性病仓不同，本仓筛查随访只有共病 PMR「医生已安排的随访」与影像复查，无任何风险判读）。

## 四、数据层纪律

- ORDER BY rowid；显式 null（不用空串冒充）；in_use 字段；分节 *_title；分类不进趋势。
- 无 diagnosis / risk_level / activity_score 类判定列；ESR/CRP 不生成「疾病活动度」派生判定。
- 演示数据唯一源；切换整页联动不串档；界面标注「合成示例 / 仅演示 / 未连接宿主」。
